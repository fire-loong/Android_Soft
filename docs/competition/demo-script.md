# ActionLoop 演示脚本（WP14 逐场景讲解稿）

> 用途：录制参赛演示视频与现场答辩时逐场景讲解。默认 6–7 分钟。
> 原则：只演示仓库里真实存在、可当场复现的功能；未在真机/真实凭证下验证的镜头标注「待补录」，禁止用模拟器、旧版本或剪辑冒充。
> 本文件中的「已可录」指当前仓库代码 + 本机环境可完整重放；「待补录」需要真机/凭证，见文末清单。

## 0. 录制前置

1. 启动依赖：PG 5433、Redis 6379 已运行（若用 `docker-compose.local.yml`，其默认 PG 端口为 5432，需设置 `ACTIONLOOP_DB_PORT=5432`）；`.env.local` 含非占位 `ACTIONLOOP_JWT_SECRET`，本地联调设 `ACTIONLOOP_RL_REGISTER_MAX=0`、`ACTIONLOOP_RL_LOGIN_MAX=0`、`ACTIONLOOP_RL_REFRESH_MAX=0`。
2. 启动 API：`java -jar services/api/target/actionloop-api.jar`；启动 Web：`pnpm --filter @actionloop/web dev`（5173）。
3. 使用全新注册账号演示，避免真实个人信息；演示数据全部为自造脱敏文本。
4. 录屏分辨率 1080p，浏览器缩放 100%，关闭通知弹窗与个人书签栏。

## 2. 逐场旁白（可录部分）

**0 开场**
「日常事务散落在通知、截图、文件和群聊里。我们不是再做一个待办清单，而是让信息先变成有原文依据的事项，再变成可协作、可核验、可追溯的完成记录。」

**1 信息进入**
「一条课程通知进来后，系统先给出候选，而不是直接建提醒。这里能看到提取出的标题和截止时间，也能一键回到原文证据；只有用户点确认，事项才真正建立。」

**2 低置信日期**
「同一段文字出现两个日期时，系统不会替用户猜。它要求显式核对，确认前不允许创建，创建后也不会自动塞一个默认提醒。」

**3–4 执行与核验**
「事项被拆成步骤和材料。完成不是点一下勾选框，而是提交说明与凭证，由有权限的成员核验；核验记录保留历史，被驳回可以重新提交。」

**5 记忆**
「处理过的资料沉淀成个人记忆。搜索既能按关键词，也能按语义找回当时那张截图，并直接跳回关联事项。」

**6–7 流程与协作**
「办事流程的每个事实性步骤都带来源版本；来源变化会触发复核。协作空间里责任唯一、状态透明，完成标准由程序判断或授权成员核验，AI 不直接改状态。」

**11 工程证据**
「这些能力都有对应的自动化证据：OpenAPI/AsyncAPI 契约检查、三端一致性脚本、k6 冒烟、上传恶意文件拒绝、备份恢复演练，以及 GitHub Actions 的八个 job 全绿。」

## 3. 禁止事项（录制与答辩通用）

- 不用模拟器画面冒充真机，不用其他机型截图冒充实测设备。
- 不演示尚未实现的能力；未验证场景只说「已设计/待验证」，并说明原因。
- 不出现真实姓名、学校、账号、聊天记录；所有样例均为自造脱敏数据。
- 不剪辑掉失败提示：低置信日期被拒、越权读取被拒等失败出口本身就是可信度证据。
- 不宣称「全部安卓机型支持」「AI 自动完成任务」等超出实测的结论。
